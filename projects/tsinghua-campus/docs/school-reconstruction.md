## 放置、正面与观察方向

遵循现有校园契约：**米制，X 东、Y 上、Z 南**。
投影中心保持 `data.metadata.center=[116.32003975,40.00164005]`，
原建筑 Group 的 `localOriginMeters` 为：

```text
[-50.32900753369005, 52.32884359304462]
```

建筑父 Group 不移动、不旋转、不缩放。细节的内部坐标轴由源轮廓
南侧长边（环点 2→3）计算：

```text
沿长边的局部东轴： [ 0.996102952, -0.088198119 ]  // X/Z
垂直长边的局部南轴：[ 0.088198119,  0.996102952 ]
```

因此 U 形开口朝北略偏西，而不是无条件朝世界 `-Z`。
入口选择源环 **点 3→4 的东南斜切边**：

```text
[116.320012808,40.001007655] → [116.320104003,40.001102169]
```

该边约 13.083 m，其外法线与建议观察方向为：

```text
frontNormalXZ = [0.804177886, 0.594388701]
frontYawDegrees = 53.530934   // 从 +Z 向 +X，南偏东
viewDirection = [0.804177886, 0.65, 0.594388701]
```

**选择东南角是依据照片长南翼／短东翼关系的方向推定，不是测绘或
摄影机外参解算。** 该边的法线本身来自冻结几何；照片没有指北标，
不能把推定方向写成已测方位。上述 viewer 方向可供父任务接线。

纯函数允许不同有限 `localOriginMeters`，以细节内部偏移抵消，
保持世界地图放置稳定；正式替换接口只接受实际源原点及原放置。

## 实际几何及尺寸

以下高度与构件尺寸均为 **照片比例推定，非测绘**：

| 项目 | 约值 |
| --- | ---: |
| 冻结地图 X/Z bbox | 111.616 × 51.691 m |
| 可见细节 X/Z bbox（含线脚、台阶） | 113.298 × 55.221 m |
| 常规墙檐口 | 9.700 m |
| 南翼主屋脊 | 13.800 m |
| 西／东两条北伸翼屋脊 | 13.600 / 13.800 m |
| 西南高亭檐口／屋脊 | 10.600 / 15.850 m |
| 东南入口高亭檐口／屋脊 | 11.150 / 17.000 m |
| 东南斜切入口整边 | 13.083 m |
| 拱门洞口宽 | 3.100 m |
| 全部可见细节实际 Y 顶（含老虎窗盖） | 17.148523 m |
| 保留的原 `baseRenderHeight` | 5.000 m |

构造不是在灰色挤出盒子上贴一张图片：

- 基础及檐下水平面按真实 U 环生成；院落及斜返角没有基座填平。
- 周墙沿源环建立，入口边用带真实拱形孔的薄墙替代整块实心墙，
  门板后退；柱、柱础、柱头、额枋、拱圈、栏杆和台阶均为几何。
- 南长翼、东西北伸翼、西南高亭及东南入口高亭为五个不相交的
  多边形屋顶区。使用现有 `polygon-clipping` 将每个平面坡面的
  hip-sector 与各区真实多边形求交，然后由 Three.js 三角化。
  **没有复制大礼堂的手写三角形半平面裁剪器，也不需要新增共享 helper。**
- 主屋面投影三角形总面积等于实际轮廓面积；每个三角形的顶点、
  中点及内部样本均在冻结轮廓内，红色坡面不跨越凹口。
- 老虎窗有拱形前面、深色窗板及独立红色小盖；入口前有低白栏板
  和高角墩。白色细线脚可微量出檐，入口台阶向外，但不封闭院落。

### 合批与纹理

- **8 个 Mesh / 主颜色通道预计 8 次 draw call**（不含父任务其他建筑，
  也不将额外阴影通道计入此数）。
- **25,390 triangles**，**7 份共享材质**；主屋顶与老虎窗盖共享材质。
  窗框、栏杆、柱和小构件已按材质合并，不是成百上千独立节点。
- 灰砌块／红瓦分别是 **128 × 128** 的确定性 CPU `DataTexture`。
  全部 Node-safe；不需要 DOM、Canvas、照片像素或网络访问。
- 两个过程纹理共约 128 KiB RGBA 像素，不创建逐瓦／逐砖网格。

## 集成接口及元数据

```js
import {SCHOOL_ID, refineSchool} from './school-refinement.js';

const target = refineSchool(campus, data, {});
// target === campus.buildings.get(SCHOOL_ID)
```

- 调用既有 `replaceBuilding`，返回**原地址可寻的建筑 Group**。
  原 `base` 保留但隐藏，其他建筑和原始 FeatureCollection 不变。
- 纯 detail 尚未挂接时带 `featureId` 以验证归属；挂接时由父任务修正的
  `replaceBuilding` 转为 `buildingFeatureId` 并移除 detail 的 `featureId`。
  因而只有原建筑根 Group 可寻址，不把细节算成第 651 个建筑。
  本模块测试校验挂接及重复替换后的该约定。
- `name` 与 Group 的 `.name` 都设为 `清华学堂`；
  `referenceSite='tsinghua-school'`、`reconstructionBatch=3`、
  `heightSource='照片比例推定，非测绘'`，附中文专项
  `refinementSummary`、`referencePages`、`referenceImages`、`limits`、
  尺寸、入口方向与无照片纹理声明。
- `baseRenderHeight` 在第一次替换保存，重复调用不会被估算高度覆盖。
- `renderHeight` 来自**尚未挂接的可见新细节网格的本地 Y 顶**，
  不是 `Box3.setFromObject(target)`。Three.js 的后者会包括隐藏基座，
  还可能包含父级世界变换；测试刻意把隐藏 base 拉高至 100 m，
  给校园父 Group 加平移、缩放、旋转，估算高度仍为 17.148523 m。
- 重复调用只保留一份细节，并释放本模块上一份几何、材质和纹理。
- 纯接口 `createSchoolDetail(feature, center, localOriginMeters, options={})`
  返回未附着的 Group，供测试或独立集成使用。
- 第一版 `options` 仅支持空普通对象；未知缩放／朝向选项明确拒绝，
  不 silently ignore 或引入未审阅默认值。

父任务只需注册该 ID 与调用函数；本次没有改 `refinements.js`、
`main.js`、模型契约、UI 或导出逻辑。
