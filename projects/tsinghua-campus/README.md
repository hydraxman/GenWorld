# 清华园 · 三维重建工作台

基于 OpenFreeMap 冻结轮廓的北京清华主校区 Three.js 工作台，支持逐栋照片参照建模、独立地标与选中对象 GLB 导出，不提供整校 GLB 导出。地图基模、局部重建和全轮廓估算明确区分，**不是实测模型，也不代表全校园已完整复刻**。身份依据、朝向推定与建模约束见 [MODELING.md](MODELING.md)。

快捷视角覆盖历史馆舍、主楼与经管组团，也包括艺术博物馆、综合体育馆和蒙民伟音乐厅等现代建筑；每处都保留独立地图身份与建模限制。

舜德楼直接复用 `projects/shunde/src/model.js` 的完整建筑及原程序 PBR：瓷砖网格、灰粉窗下板、深褐入口石材、柱石的颜色／法线／粗糙度，不再以纯色降级。保留既有精调窗洞、打开的入口和示意门厅、原尺度、ENU定位及通建华连廊；未重新搭建近似外壳。独立演示的550米地面和高密度植物不迁入校园，继续使用校园地图与树木层；移除的资源与保留建筑共享材质时不提前释放。楼牌使用系统字形示意，不发布原照片提取字形。Pages 首页不再单列舜德入口，校园内 `?view=shunde`、目录与 `?visit=shunde` 保持可用。

点击建筑或目录条目可查看“校史与建筑”知识卡片，快捷视角后也可用顶部“知识卡片”打开。已收录19处建筑／组团的简要校史、建筑观察与逐条来源，依据13个校方一手来源；未收录对象显示“暂无校史资料”。模型参数收在“模型尺寸”中。摘要随离线包内嵌，来源网页仅在点击时打开。界面不再展示建模免责声明、覆盖率长说明和无知识意义的口号；依据、未知项与资产许可继续保存在源数据及维护文档。内容维护见 [校史与建筑资料](docs/BUILDING-HISTORY.md)。

当前冻结地图的 **650个建筑根均有建筑模型**：40个照片参照／原模型复用根，另有610个明确标记的程序建筑估算，已无仅显示原始挤出体的根。后者按可靠OSM建筑类型分型，包含几何窗洞、退入玻璃、窗框窗台、入口、屋面与压顶；亭廊和看台保留开敞构造。**根的结构覆盖率不是全轮廓还原度，也不证明地图覆盖最新全部实物建筑**。程序估算和局部／组团照片模型仍保留在照片核实待办中。

其中 **16个轮廓**进一步使用15处具名校方来源的18张照片，调整墙面、窗带、屋顶配色与有限特征；覆盖一至六教、廖凯原法律图书馆、人文社科图书馆、明理楼、新旧水利馆、明斋、古月堂和建筑馆报告厅。顶部“实景配色”可逐栋切换，侧栏提供原发布页与未知项。它们仍属于程序估算，不增加40个照片参照／复用根的计数；裁切入口照、合并轮廓、未入镜屋顶和高度比例均保留限制。六教A/C导览使用同一张外景，不能当作两个翼楼逐面核实。远景合批也保留各自配色，不只在近景生效。

二教、三教一二段、三教三段、新水利馆和明理楼进一步细化照片可辨认的入口：真实退入开口、拱廊／方柱雨棚、三联拱券及中央玻璃门厅，不用普通窗前叠细杆代替。选中后可点“查看入口细节”；入口所在边显式记证，未入镜面和尺寸仍是估算。

原 **Courtyard南立面、屋顶、露台栏杆、三段干石池与双廊架直接复用**到老生物学馆的原地图根。仅替换旧北墙及北窗，依桥向照片加入石质门厅、真正凹入的门窗、台阶、分层竖窗和阶梯女儿墙；其他源三角面保持不变。北面继续使用原建筑的砖石和玻璃材质。原模型约34m宽，与地图约70m宽轮廓不完全一致；不拉伸或续建，尺寸、回墙与保留原屋顶的衔接仍是估算，不是全楼测绘。**老生物学馆不是北侧伟伦生命科学馆**，后者原身份不变。

全校程序建筑直接复用 `shared/pbr.js` 的Courtyard砖石生成方法，256px共享颜色／法线／独立粗糙度；已有照片配色和精细纹理保留。未贴图的具名石材、抹灰、屋面及道路接入四套共享表面。玻璃使用一个近景局部场景探针（桌面128px、手机布局64px，最多每秒一次，位置随观察区域更新）；水系沿用原地图合并面与洞，在Courtyard的Fresnel／平面倒影基础上接入Qingming微法线纹理与七层波函数，仍只有一个倒影目标（512／256px，最多8次／秒）。两者不是每栋楼／每片水面一套。默认暂停并缓存静止画面；可开启“水面与垂柳动效”，隐藏标签页暂停，全校远景和平面图不捕获倒影。单一局部探针并非逐窗精确倒影，移动端布局测试不代表真机帧率。可关闭“近景倒影”；单栋GLB保留PBR材质，不携带运行时反射贴图。

普通住宅／宿舍类与紫荆外墙进一步直接复用舜德的 `square-grid` 瓷砖生成器：1.68m内16格、单格10.5cm，共享一套512px颜色／法线／粗糙度图；原照片配色建筑不改成统一瓷砖。共用砖石、抹灰、压顶及道路表面按米制UV映射，避免整块墙／楼板拉伸一张小图。纹理不随楼栋数量增加，也不新增反射目标。

校园批量建筑和紫荆楼板不再重复生成与外墙共面的侧边，保留楼板上下表面、连续围护、门窗及庭院开口；消除层间断续缝线而非通过放大外壳遮挡。紫荆高层压顶补齐连续女儿墙支承，不再悬浮。`node scripts/envelope-check.mjs` 对教学楼、住宅及紫荆三种楼型记录桌面／手机固定近景与三种照明，`ENVELOPE_CAPTURE=before` 保留修改前对照，`CAMPUS_QA_URL` 可核对Pages。

紫荆组团已覆盖本轮有来源的 **1–23号公寓**，并加入紫荆园、桃李园餐厅。坡顶本科生楼、W形博士楼、条形高层分型建模；楼号菜单支持逐栋查看、拾取和GLB导出。14–17原来共用一个地图根，现按独立OSM边界在根内分楼，未增加或偷换地图身份。**这些是组团照片约束的类型估算，不是每栋逐面照片验证**；未确认高度、窗位、屋顶分配及更新楼号仍有说明。

加入东大操场、西大操场、紫荆操场及周边球场，共 **41个冻结OSM运动场多边形**；顶部“操场”菜单可直达三个主场。外边界来自地图，裁切校园范围并避开建筑；附中操场与跑道不混作大学操场。紫荆已有地图跑道时沿原线展示，其他无独立跑道记录的主场采用明确标注的示意跑道；道数、线宽、内部场线和配色均非实测。

绿地使用原创、低对比度的米制草坪纹理，独立颜色、微法线和粗糙度通道。**650株实例化树木**复用Courtyard分枝算法与同一裂叶轮廓，远景不再是球冠；近处才显示单片叶子，同时最多桌面12株、手机4株。树位不变：19株采用可安全展示的地图树位，631株为绿地内示意种植。校园边界内另有47个地图树位因建筑／道路／运动场冲突不展示，不迁移到虚构位置。树种、冠幅和高度未知；不是树木普查结果。操场、树木可独立关闭，不随选中建筑导出。

低空透视使用320m空间树簇进行视锥裁剪，共用原几何和材质；高空及平面图仍使用两个全图实例批次，避免为远景增加大量绘制调用。近叶同时从全图树冠与空间簇中替换，切换视角不叠加两套树。水面高光方向、颜色和强度跟随场景实际太阳光，与背景天空和玻璃环境共同构成展示光照。

水面反射相机同时镜像偏轴投影的水平主点，适配为侧栏留位的取景；可见水面不会在屏幕一侧突然切回天空采样。仍使用原来的单个反射目标，不增加捕获次数。

河岸另复用 **Qingming原作垂柳Auto1模型、烘焙叶簇贴图与微风变形代码**，不是重新画一个近似树。实例共用四个部件，近景最多桌面12株／手机6株；与原创石岸、岸草、静态人物、自行车、长椅和路灯共用不超过12个绘制批次。按冻结道路／水边布置并避开建筑、操场和道路冲突，远景关闭、近处限额显示；不增加建筑根，不随单栋导出。布置、人数、植栽和河岸工程均为示意，非实测现状，也未移植古城建筑或完整模拟系统。

## 运行

从完整仓库使用本项目：校园会复用兄弟项目的庭院／舜德源码与定位数据，但默认运行不需要任何项目的参考照片。

```sh
cd projects/tsinghua-campus
npm ci
npm test
npm run build
npm run dev
```

访问 <http://127.0.0.1:8786/>；`?view=old-library` 等参数可直接打开已注册视角。Windows 可运行 `start-preview.cmd` 并保持窗口打开，关闭窗口即停止服务。

紫荆可用 `?view=zijing` 打开全组团，`?view=zijing-14` 直接查看指定楼号；餐厅视角为 `?view=zijing-dining`、`?view=taoli-dining`。

`?view=biology-hall` 查看直接复用的原南向庭院，`?view=biology-north` 查看同一建筑经照片细化的北侧桥向入口；非北面源几何不变。

`?view=sem` 查看经管建华／李华组团，`?view=jianhua` 直达建华楼北门。清华官文与Gensler照片支持玻璃后方17m白拱、点支幕墙、局部高拱窗、大板陶板端墙、薄檐玻璃翼及悬挑圆柱；共用Shunde源模型同步更新。北门沿边位置、宽厚、内部侧廊、玻璃翼退距和隐藏面仍为推定，不拆分原合并地图根；通舜德示意连廊不冒称官方“知识之桥”。

`?view=jianhua-passage` 查看**建华北侧架空**：用户桌面“经管北向楼体”与官方原图哈希一致，确认红楼与东侧低层之间向庭院贯通，上方连续玻璃楼体跨越；东侧下层玻璃退入，粗银色圆柱与金属底板相接。通舜德的窄玻璃桥对齐玻璃翼下沿，不与中间连接体混同。分界、约22.1m开口宽、9.76m净高、6.5m退距和1.96m柱径均为比例估算；原横向17m通道保留为未核实的平面推定，不能再用这张北向照片证明其位置。北门白拱的17m则另有官方文字依据。

退入的下层前墙与两侧墙共用连续转角，窗格和陶板竖片不伸入架空区。通舜德桥保留建华侧北部落点，另一端斜接舜德**实际西墙范围内**，两端连同屋面边缘接实；不能把地图边的无限延长线当作墙面。未移动原楼体，斜接路线和收口尺寸仍是模型估算，不表示已开放连廊内部漫游。

玻璃翼与红楼交接的短退台边按用户红圈纠正为无窗红色实墙；玻璃翼及其屋顶、底板、檐线止于内转角，不再向红楼外转角伸出一排窗格。修正作用于共用源几何和单栋GLB，不是仅在校园视图中隐藏。冻结轮廓、正面幕墙、架空净高、银柱和连桥保留，具体分界仍为估算。

该红墙按用户特写补齐四行立体院名：`清华大学`、`经济管理学院`、`SCHOOL OF ECONOMICS AND MANAGEMENT`、`TSINGHUA UNIVERSITY`。字样和行序有照片依据，OFL文楷字形、大小、安装位置及金属色为近似，不是原书法。四行分别合批，新增少于2万三角面、无新增贴图或网络字体；手机、离线与单栋GLB共用同一挤出几何。可选字形重提取入口见[Shunde说明](../shunde/README.md)。

天空改为明亮蓝天与白色云团，启动时只生成一次原创1024×512全景纹理；背景、预滤波环境和水面共享同一天空。远景、俯视及关闭近景倒影时，水面按反射方向采样蓝天白云，不退回暗绿／浅绿纯色。纹理约2MiB（含mipmap约2.67MiB），不下载HDRI、不逐帧计算云噪声；云层静止，不增加反射捕获目标。局部倒影按相机到水面实际距离在220–380m渐退，高空不继续捕获无用倒影。加强的天空反射为展示效果，不是实测水色或水体光学仿真。

校园外围不再是纯色大平面：边界外的草地和疏密树带接入城市街区，住宅长楼、较高的办公体量、屋顶退台与公园间隔构成中景，更远的楼群渐淡至蓝天地平线。草地复用校园已有三张程序纹理，叠加低频色差；新增窗格仅一张64px纹理。外围为确定性程序环境，不是周边真实建筑复原，身份依据仅保留在维护文档和源元数据，不增加画面说明。

`src/surroundings.js` 独立于权威校园树：650个原建筑根、庭院孔洞、相机取景范围、点击和单栋导出不变。楼群、道路与树冠避开冻结校园边界及跨界建筑的保护范围；四区实例共用几何和材质，不计算背景实时投影、不新增倒影目标。基础绘制最多20次、26万三角面、2MiB几何及实例数据；近景开启GTAO时法线通道还需绘制一次，不把单通道预算冒称完整帧成本。无后台动画或网络素材，平面模式关闭空气透视，离线包内嵌同一环境。

“进入建筑”菜单或 `?visit=shunde`、`?visit=jianhua` 进入舜德楼门厅／建华楼北门中庭。门洞和向内打开的门扇为真实几何，可以从入口走入并转身查看；WASD／方向键移动，Q/E转向，拖动环视，手机可按住屏幕按钮，Esc或“退出漫游”回到原外观视角。墙面、边界及座椅有碰撞限制。**仅开放示意门厅，不是整栋室内、楼层或真实室内陈设的复原**；入口外观的照片依据不延伸为室内依据。`visit`、`view`、`building`、`ground` 参数互斥。

顶部“舜德楼 · 知识展台”进入同一门厅。入楼过渡沿真实门洞到达源坐标入口终点，移动或拖动立即接管；减少动态偏好保留手动行走。手机按触屏面板上方的可见区域取景，退出恢复原视角。门厅增加木饰面、石材内衬、顶面灯带与简洁导览。最短路、链表和马尔可夫荷塘三张实体展台，走近并面向时亮起桌边提示，可按 F、触屏互动按钮、桌面或名称展开；图解升至桌面上方，提供 BFS／Dijkstra 对照、链表插入／删除／逐步反转、青蛙按当前荷叶概率跳跃及九道解释题。查看展台期间暂停移动，Esc先收起展台，再按Esc退出漫游。

这套教学展台复用知识大厦的 `shared/knowledge-labs/`，没有嵌套 iframe 或第二个渲染器。展台与内衬只在进入门厅时创建，桌面和后墙内衬加入碰撞，退出释放临时几何／材质；两套共六张 PBR 图由宿主缓存并统一释放。它们位于运行时展示树，不进入建筑GLB、不改变650个根或原建筑几何。操作和题目暂不写入掌握度，关闭重置，离线包可用。[Long Wind 核验](docs/LONG-WIND-REUSE.md)记录参考实现与许可边界，本轮未复制其角色、动画或渲染器。

`?view=riverside` 查看石岸、垂柳和水面；`?view=campus-life` 查看近景人物与街景。“河岸”和“街景”可分别关闭；人物为静态姿态，动效仅作用于水波和复用的垂柳。

所有地图轮廓均可通过目录分页访问，包括未命名对象；支持程序类型筛选和“只看照片参照”筛选。选中对象后“打开此建筑独立链接”生成 `?building=<稳定编号>`，可直接打开任意建筑，也适用于离线单文件。不能与 `?view=` 同时指定。

操场直达参数为 `?ground=osm:way:32954674`（东）、`?ground=osm:way:32954848`（西）、`?ground=osm:way:32954864`（紫荆）；不能与建筑／快捷视角参数同时指定。

默认构建生成 `output/tsinghua-campus-offline.html` 单文件工作台和 `output/reference-photos.html` 来源元数据页。模型与地图内嵌，无在线地图或 CDN 依赖；来源链接仅在点击时访问。来源页不读取或复制照片，明确标注图像字节未校验。

## 使用与验证

- 拖动旋转、右键平移、滚轮缩放；平面模式北向上。搜索名称／编号或点选对象，可查看来源、估高依据与局部原点。
- “建筑目录”和“图层”可收起；手机默认让出画面，通过横向滑动快捷栏切换地标。视角根据未被工具栏遮挡的区域取景，近景阴影随关注范围调整。
- 快捷视角、地图图层和“只看照片参照建筑与地标”筛选可组合使用。程序建筑类型仅来自建筑轮廓重叠核验，未匹配用途保留未知；不能从轮廓内商户推断整栋用途。紫荆／教学片区是工作区段，不是行政分区。
- 页面先绘出真实地图，再分帧构建照片模型和运动场，并显示进度；610个程序建筑只为进入视锥的近景按需构建窗洞，每帧最多准备两栋，完成前保留远壳，不能将延迟构建当作删减模型。公开Pages把GLB导出器拆成点击导出后加载的模块，离线单文件仍完全内嵌。手机最高1.5倍像素比、桌面1.75倍，避免高DPI过度填充。
- 全校远景将程序建筑合并为可逐栋拾取的批次，近景恢复真实窗洞等几何。“建筑近景细节”仅控制程序建筑；精细模型另由 `src/display-lod.js` 派生显示批次，原始根、几何和导出不变。支持 `WEBGL_multi_draw` 时按材质等状态合批，复制内存相对节省调用过高的组不合批；无扩展设备保留源网格。中远景只按实际输出像素省略已明确登记的亚像素细杆／接缝，不删墙、窗洞、玻璃、柱子、屋顶或连桥；阈值带回切滞后，近景恢复全部结构。
- “三维细节阴影”增强近景接触层次，手机默认关闭；方向光投影限于局部近景，避免全校阴影成本与伪影。程序天空、环境反射和AgX为展示光照，并非实地时刻。
- 透视相机近平面随焦点距离调整，并为地图各表面保留确定的深度偏移；修复校园与背景地面近乎共面时的远景深度竞争，不靠隐藏道路／绿地掩盖闪烁。
- 仅保留“导出选中 GLB”，支持单栋、地标和选定紫荆楼号；不提供整校导出。**始终导出选中对象的完整建筑结构，不随相机距离或细节显示开关降级**。采用自身局部原点，米制、Y 向上，保留身份和来源；不包含其他建筑及校园景观图层。
- `npm test` 覆盖几何、身份、来源元数据、冻结输入哈希和离线重放；照片字节检查默认明确跳过，不计作照片验证通过。
- `npm run qa` 是可选浏览器／GLB 验收，检查实际渲染的窗墙明暗差与外观开关，生成截图汇总、覆盖报告和待完善清单；需要本地 Edge，或通过 `CHROME_PATH` 指定浏览器。明暗指标、几何测试和导出成功均不能代替照片对照。
- `node scripts/performance-check.mjs` 使用同一Edge ANGLE D3D11驱动测量桌面／手机冷页面首图、就绪、最长主线程任务和实际绘制时间，结果与截图留在忽略的`output/`；同时复测毫米级相机移动的真实像素变化，超过0.2%即失败。它不是跨机器跑分；`CAMPUS_QA_URL` 可指定已构建／发布的入口。
- `node scripts/optimization-check.mjs` 在同一页面、固定机位对照原始／优化显示，检查调用、三角形和额外批次内存，逐视角比较实际像素，并验证太阳／水面方向一致、19处知识卡片、键盘打开、手机排版与离线零网络。`renderer.info` 统计完整绘制帧，包括当帧实际执行的阴影、反射及后处理，不把GTAO最后的全屏绘制误算成全场景一次调用。结果不代表真手机帧率或跨设备保证。
- `node scripts/surroundings-check.mjs` 捕获桌面／手机的全校、紫荆、屋顶平视与平面机位，对照背景开关的真实像素及完整帧成本，并验证原建筑选择、入楼、纹理稳定与离线零网络。`SURROUNDINGS_CAPTURE=before` 留存旧版同机位基线，`CAMPUS_QA_URL` 可核验Pages；输出留在忽略目录。`tests/surroundings.test.mjs` 检查确定性、全范围边界排除、树冠退让、资源共享与释放。
- `node scripts/look-check.mjs` 固定北门、门厅和水岸相机，捕获展示／中性／掠射光对照；验证实际水面倒影像素、玻璃共享探针、18张共享表面纹理、纹理所有权释放和静止缓存。`LOOK_CAPTURE=before` 可对旧发布页记录同机位基线，`CAMPUS_QA_URL` 可指向新发布页；照片与生成截图均不入库。
- `node scripts/jianhua-check.mjs` 在构建后捕获经管全景、北门三种光线、玻璃翼及架空通道；检查桌面／手机的白拱可读性、合批与纹理限额、北门／通道导航。临时远端色块验证两个出口的实际渲染无遮挡，随后立即移除；实际单栋GLB重新加载后以双面射线验证全高通行净空。`JIANHUA_CAPTURE=before`（或以`-before`结尾）与 `CAMPUS_QA_URL` 可记录旧发布页同机位对照；比较图不入库。
- `node scripts/north-water-check.mjs` 捕获北向整体、开口、银柱和连廊两端，检查下层架空区无多余窗片，并以30条射线验证桥两端完整断面与实际楼体接实。另检查桌面／手机／离线的蓝天与白云真实像素、同一天空纹理复用，以及近水、俯视、远景、平面和距离阈值；远景必须有云影明暗变化且不捕获场景倒影。`NORTH_WATER_CAPTURE=before`（或以`before`结尾）保留同机位基线，`CAMPUS_QA_URL` 核验发布入口；截图、报告与参考照片均不入库。
- `node scripts/scenery-check.mjs` 验证桌面／手机／离线的河岸和街景可见像素、实例限额、图层开关、水波／微风的固定时间重放及暂停，并复测单栋、地标、楼号导出。
- `node scripts/walkthrough-check.mjs` 用真实键盘／按住按钮走入两栋建筑，拖动转身查看，复测移动端尺寸变化和退出恢复。单元测试另以双面射线验证实际门洞及脚下地板，不只验证相机坐标。两项脚本均支持 `CAMPUS_QA_URL`，离线用构建出的单文件，截图不入库。
- 仓库根目录 `npm run test:labs` 检查三种实验的计算、概率守恒、指针重连、展台高度与碰撞；构建 Pages 和校园离线包后运行 `npm run qa:labs`，检查两个宿主的桌面／手机操作、三维拾取、九题反馈、收起恢复与离线零网络。`PAGES_URL` 可指定已发布的站点根地址；截图和结果保存在忽略的 `output/`。

仅在合法持有所需本地参考文件时，显式运行：

```sh
npm run test:references
npm run build:references
```

严格测试保留原有哈希、尺寸与字节断言，涵盖独立来源记录及审阅衍生图；缺图或不符即失败，不联网补图。严格构建校验共享索引中的照片哈希后才复制到本地图册。它们不授予再发布许可。

**默认构建不会清除旧的 `output/references/`。公开分发时不要携带本地照片、旧图库或参考截图。**

## 数据与扩展

- `data/` 保存冻结地图与匹配证据；`source-cache.json` 是必要的离线输入，不是可删临时缓存。保留原字节、哈希和 `.gitattributes` 的 LF 规则。
- `npm run data -- --offline` 从冻结输入重建数据，不依赖原始 PBF 或网络；只有明确更新来源时才使用 `--refresh`，并重新审核身份匹配。
- `src/reference-catalog.js` 合并原 `reference-catalog.json` 与 `data/appearance-profiles.json` 的来源元数据，共34处、56张；独立 `data/*-references.json` 还保留补充证据及审阅图记录，不能按图库数量删减。收录照片不等于已按它重建。
- `src/model.js` 提供地图模型与替换接口，`src/refinements.js` 注册建筑，`src/landmarks.js` 注册独立地标。新增模型遵循 [建模约束](MODELING.md#建模约束)。
- `src/campus-architecture.js` 只补齐仍无照片模型的轮廓，不覆盖已有照片参照模型。`data/architecture-evidence.json` 保存650个原轮廓的核验签名与建筑标签来源；`node scripts/architecture-evidence.mjs` 从冻结校园和兄弟项目的原始OSM离线重建证据。匹配要求单一闭合建筑way、投影交并比不低于0.8，并拒绝近似并列；不替换轮廓、不沿用最近名称。当前478个轮廓有明确匹配，其余172个不借用邻楼标签。明确地上层数标签可按估算3.2m层高调整显示高度；另有显式记录的照片比例估高，均标为非实测。无上述依据继续保留原地图显示值。
- `data/appearance-profiles.json` 保存16个外观档案的原编号、具名OSM来源、几何签名、照片哈希、配色与可见／未知项。`src/photo-appearance.js` 在替换前核验身份；照片不跨楼借用，六教A的具名way只覆盖合并根的一部分，单独声明并回放重叠。来源照片只供本地对照，不打包为材质。
- `node scripts/landscape-evidence.mjs` 从既有OSM和校园边界离线重放运动场与树位证据，保留原始文件SHA-256、运动场原边界、裁切边界与附中排除项；不采集联系人等无关标签。650个建筑记录不变，景观不增加建筑身份。`src/landscape.js` 使用合批面与实例化树木；Courtyard分枝的裂叶轮廓沿用既有CC0素材，叶色与草坪为原创程序通道；额外垂柳和水面微纹理来自下述MIT资产。
- Qingming固定版本为 `81f5c0a6e78e67388cc8a978064b88c53621949e`。`src/vendor/qingming/` 仅保存所需柳树部件、512px叶簇、256px微法线及原许可证；`src/qingming-reuse.js` 适配原七层有限水深波函数与顶点微风，保留Auto1在上游继承的原作叶色。需要重新提取时运行 `python scripts/import-qingming.py`：从忽略目录`output/qingming-source`的固定检出及`output/Qingming_Auto_Details.glb`读取，要求Pillow；源GLB的SHA-256为`6b8a9facc67f73e2fbbe372c549202b07da13733ec7e1751c6e67a3c135afd2f`。完整克隆和73MB源GLB不提交、不发布，正常构建不需要它们或网络下载。
- `npm run assets:pack` 从保留的Qingming源快照确定性生成 `src/vendor/qingming/runtime.json`。运行时使用原生 `DecompressionStream('deflate')` 一次性还原RGBA，逐字节保持原像素与几何；无需新增解码依赖、WASM或下载。普通构建和Pages构建会拒绝过期产物。压缩减少嵌入包体，不减少解压后纹理显存，也不能直接等同网络传输降幅。
- [参考照片库](docs/REFERENCE-LIBRARY.md) 登记96个本地照片文件的尺寸、哈希、来源与权限，其中15个来源未解决；仅3张许可已核实的CC BY-SA原图进入 `docs/reference-photos/`，其余研究副本仍留在忽略目录。`node scripts/reference-library.mjs` 核验档案及仍存在的研究照片，`--require-local` 要求全部本地照片齐备；缺失不算验证通过。新出现照片必须先登记。根目录可运行 `node projects/tsinghua-campus/scripts/reference-library.mjs --published output/pages` 检查已登记原始像素与参考目录未泄漏到公开构建。

### 独立庭院预览

`node scripts/courtyard-preview.mjs` 生成 `output/library-courtyard-source-preview.html`，通过上述预览服务打开。它独立展示同一 `../courtyard/src/model.js` 的建筑、三段干石池和双廊架，并可导出未带校园定位的 `library-courtyard-reused-unplaced.glb`。校园定位由 `src/biology-hall.js` 另行挂接，不修改源模型几何。它不是老图书馆东翼入口；石池及既有造型不能当作实测现状。
