# 制作方法

## 实际制作链路

本片先使用 OpenFreeMap / MapLibre 在线地图数据，在本地后台浏览器中按绝对时间逐帧捕获；中间版本曾使用 HyperFrames 合成。最终 V5 使用冻结后的画面直接交给 FFmpeg 编码，并复制已批准的 AAC 音轨，不再要求 HyperFrames，也未使用 GPU 云服务或 DSX。

“冻结”指照片、音频、路线、样式、时序和已经捕获的画面固定下来。地图渲染阶段仍依赖浏览器和在线地图资源。只有画面缓存完整后，最终编码才可脱离在线瓦片；不能把整个流程写成纯离线，或认为只有代码而无需浏览器就能还原画面。

## 1. 来源与坐标

以 [`SOURCES.md`](SOURCES.md)、`photos/all-manifest.json`、`assets-manifest.json` 核对每站名称、照片和出处。来源页面可访问不等于图片获准转载；公开地图接口可返回瓦片也不等于拥有任意导出或商用权利。改用新图源前，先确认许可、署名与真实分辨率。

路线读取 `route.json`，原始路网读取 `campus.osm`：

- CRS 为 WGS84，坐标数组采用 `[经度, 纬度]`。不要混入未经转换的 GCJ-02 / BD-09 坐标。
- `point` 是景点位置，`road_point` / `road_node` 是路线上停留点；`snap_m` 记录二者距离。不能把建筑中心当作实际入口。
- 路径沿 OSM 道路节点连接，按 `legs` 和源路网检查连续性、禁行与障碍，不能用景点间直线替代。
- 十二站全长约 4.62 km，顺序兼顾既定内容与连贯游览，不声称全局最短。局部折返不等于数据错误；应检查具体路段，而不是为视觉平滑穿过建筑或水面。
- OSM 快照和旁白不是实时通行许可；保留预约、现场开放与访客用餐提醒。

## 2. 冻结素材和声音

保留十二张核心照片的自然比例、水印及来源，逐站核对，不用相似建筑代替缺图。确认字体覆盖对联全部正文，并保留 `fonts/OFL.txt`。照片只在对应停留时段展示，移动地图焦点给照片留位置；对联段可使用更大的照片和书法文字。

旁白按十五段分别存档，先测量真实 WAV 时长，再安排停留时间。`timing.json` 是批准版帧级时间表，`audio/approved-narration.m4a` 是最终合成使用的原速 AAC。仅切底图或调整开场画面，不重新合成、不变速、不重排音轨。重新配音属于另一轮制作，详见 [VOICEOVER.md](VOICEOVER.md)。

## 3. 绝对时间镜头与开场映射

每个画面由目标帧及冻结输入决定，不依赖“上一帧运行了多久”。镜头读取路线累计距离、移动段与停留段，按绝对时间计算中心、缩放、俯仰和路线进度；照片、标签和对联同样由时间确定。这样才能直接跳帧、抽查边界和恢复捕获。

V5 保留 17 秒前快后慢聚焦：二次 ease-out 重映射开场的源时间，随后沿用既定时间线。17 秒是聚焦镜头长度，不是整段开场旁白或 `intro` 时槽长度。不能将画面与音轨一起加速，也不能用恒速加速后补静止画面替代原曲线。

`intro-remap.json` 冻结了包括端点在内的 409 项源帧映射。Python 与 JavaScript 共用这份数组，不在两端各自计算取整：Python 的 ties-to-even 与 JavaScript 的半帧处理可能在精确半帧处差一帧。验收应检查中间地理位置、17 秒衔接处和开场之后的映射，不能用放宽全片误差容限掩盖差异。

## 4. 两种底图共用一条生产线

| 模式 | 地图层 | 背景 | 缓存根目录 |
| --- | --- | --- | --- |
| `standard` | OpenFreeMap 矢量地图，含 OSM 道路、地名、建筑表达 | `stars.svg` | `output/standard/` |
| `satellite` | EOxCloudless 2025 约 10 米影像，叠加 OSM 辅助层 | `stars.svg` | `output/satellite/` |

切换用 `--basemap standard` 或 `--basemap satellite`，缺省为卫星。两者使用同一页面、路线、时序和音轨。普通地图不要求白背景；卫星模式也不能把矢量楼块当作真实三维摄影测量。最终卫星图源不是 Esri，影像不代表当前现场。

星空放在透明地图画布后方，地球瓦片遮住球体区域。抽查首帧是否有完整地球、星空和意外露出的校园标签，再看校园近景；只看 CSS 中的透明度不能证明最终截图正确。修改卫星样式时保留需要的地名和路线，并检查高缩放下楼块层的生效区间。

所有命令从 `projects/tsinghua-tour` 执行：

```sh
npm ci
python3 -m pip install -r requirements.txt
npm run preview -- --basemap satellite
npm run capture -- --basemap satellite
python3 tools/export.py --basemap satellite
```

重做普通版时，将三个制作命令中的 `satellite` 全部换为 `standard`。交互检查使用 `npm run serve -- --basemap standard`，在终端给出的地址上使用同页查询参数 `?basemap=standard`；不要误把另一个页面或历史截图当作本模式的预览。

## 5. 串行、可恢复的浏览器捕获

使用已安装的 Chrome / Edge / Chromium；必要时设置 `CHROME_PATH`。先完成抽样预览，再启动一个浏览器捕获任务。每次设置目标时刻后等待地图、瓦片、字体与图片就绪，保留加载失败证据。空白或未就绪的画面不算成功。

捕获支持 `--from N --to N --out 路径`，起点包含、终点不包含。中断时记录已完成范围，确认旧进程不存在，并检查已有 JPEG 可解码、与报告哈希一致后再恢复。超时返回不证明旧进程已退出。不要为了赶进度并行启动多张 MapLibre 页面，多个页面可能出现就绪超时。

重复的停留姿态可以只捕获代表帧，但缓存必须绑定页面、样式、路线、时序、照片、字体、视口与映射指纹。不同底图独立缓存，同一底图改过输入也要隔离旧缓存。只重用已验证为同一姿态的帧，不能把普通版帧复制到卫星目录凑满数量。

## 6. 母片与聊天版

完整捕获后，单独执行 `python3 tools/export.py --basemap satellite` 或普通版对应命令，避免长捕获耗尽执行窗口后连带中断编码。保持 1280×720、24 fps 和完整内容，保留高质量母片；中间可复用地图片段使用短 GOP，例如 24 fps 下 `-g 24 -keyint_min 24`，便于定位与预览。

最终版通过 FFmpeg 复制 `audio/approved-narration.m4a` 中的 AAC（`-c:a copy`），不重新编码或改变语速。比较音轨时提取相同封装形式的 AAC 再计算哈希，不比较不同容器的整个文件哈希。

聊天版另存。原 V5 以低于 30,000,000 字节为传输目标，必要时用两遍码率分配压缩视频；不靠降低分辨率、删段落或加速音轨减小体积。新的投递渠道可能有不同上限，以实际限制为准。不能把聊天压缩版覆盖母片或已批准的 `final/tsinghua-v5-satellite-stars.mp4`。

## 7. 验收和投递

```sh
npm test
python3 -m unittest discover -s tests -v
python3 tools/verify.py --video final/tsinghua-v5-satellite-stars.mp4
```

新产物必须把 `--video` 指向实际文件，不能验证旧成片后声称新版通过。`evidence/final-acceptance.json` 是归档成片的记录，不是本次运行结果；报告中区分继承的证据和新执行的检查。

验收清单：

- 核对十二站、十二张对应照片、十五段声音、三十四字正文，无漏项和重复替代。
- 用实际编码文件检查宽高、帧率、总帧数、视频时长与严格解码；批准版基线为 1280×720、24 fps、8525 帧、355.208333 秒。
- 抽取首帧、开场中间帧、聚焦衔接前后帧、每站照片、移动 / 停留边界、对联首末字与上下联交接、片尾及精确最后一帧。与源捕获对照；有损编码后不能声称像素完全相同。
- 对所有十五段核对最终 AAC 中的对应波形和起点，再逐段听完，特别检查对联读音、句尾与完整预约 / 食堂提醒。仅存在音频流不算通过。
- 检查每个模式自己的地图就绪证据、校园近景、地球星空和编码后画面。不要用卫星版验收替代普通版验收。
- 记录本次文件路径、大小、哈希、实际运行结果与未通过项；没有执行的检查明确标为未执行。
- 用户授权投递后发送明确的已验收文件，绑定目标会话与消息；回读该条消息并下载附件核对哈希后，才报告“已送达并验证”。不要将账户、会话标识或凭据写入仓库文档。

资料收集与独立审阅可以并行；素材冻结、时序生成、捕获、编码与验收按依赖顺序执行。保留原版与失败证据，不在未获授权时提交、推送或发布。
